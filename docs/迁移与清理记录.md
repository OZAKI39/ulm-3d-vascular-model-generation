# 血管打印项目迁移与清理记录

本次将血管打印相关的代码、原始数据、处理结果、模型、切片文件、论文资料和日志集中到 `/home/lzy/projects/vascular_printing`。原工作区中仍在使用的 CFD 与流场求解部分留在原位置。本次没有修改血管半径、端口形状或可视化风格，也没有向 GitHub 推送或向打印机发送任务。

## 迁移了什么

迁移前清单包含 **32,697 个文件条目，合计 28,956,773,593 字节，约 28.96 GB（26.97 GiB）**。数据在同一文件系统中实际移动，不是重新下载。迁移后首先逐文件核对哈希；完成路径适配后再次全量核对，没有发现未记录的变化。

内容包括 BraVa、TopBrain 和小鼠等血管数据，SWC 处理与 VascularMD，TopBrain 标签解析和语义迁移，MeVO 与制造 ROI，端口连接修正、ABS 框架和倒模件、Bambu 切片、检查图与日志，以及对应测试、配置和参考资料。原始数据许可和第三方仓库历史一并保留。

当前生产数据和源文件均以本目录为实际存储位置。旧工作区在对应位置保留相对符号链接，支持历史报告里的绝对路径，以及尚在运行的 CFD 对共享几何的调用。这些链接几乎不占用数据空间，不是另一份模型副本。原仓库 Git 历史、CFD 和 Network H0 仍在旧目录，不能整体删除旧目录。

迁移只复制了三个很小的共享基础文件：`utils/__init__.py`、`tests/conftest.py` 和 `requirements.txt`。误归类的一项 CFD 命令行测试已返回原项目，调整有独立记录。其余迁移项均采用移动方式。

## 为使新目录可运行做了哪些修改

八个源码或测试文件做了路径兼容调整，解决符号链接的真实路径与历史字符串路径不一致、原项目包名引用、历史哈希字典键名以及仍在旧目录的 CFD 保护文件查找问题。历史保护记录没有被改写；迁移审核会分别报告“内容未变”和“有记录的兼容修改”，同时校验修改前的归档源码与当前源码。

主入口测试另发现一个原有问题：`--skip-slicing` 不产生切片记录，生成比较表时却访问空列表的首项。已在 `bambu_casting_mold.py` 中补充固定表头，使跳过切片的运行正确生成空表。这是表格导出修复，不涉及几何或切片参数。因此，最终清单为 **32,688 个原内容不变的条目和 9 个有完整记录的源码调整**。所有 `s1-*` 可视化与主入口脚本保持原始字节。

修改前源码、逐行差异、修改前后 SHA256 和原因均见 `migration/20260926/original_sources/`、`path_compatibility.diff` 与 `path_compatibility_edits.json`。新增的迁移工具、测试和本说明不属于迁移前文件清单。

运行环境仍使用原共享虚拟环境；没有移动或重建环境。仅补齐 `h5py==3.16.0` 和 `pymeshfix==0.18.1`，既有包版本未变，`pip check` 通过。实际版本另记录于根目录 `requirements-printing.txt`。
