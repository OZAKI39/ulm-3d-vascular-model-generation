## 实际热点、Graph及计时口径

`profile_v1`使用已有 Warp 1.18 的活动计时：20物理步，无 Graph 以区分活动，插入 CUDA Event。总活动跨度11.888 ms，其中十二轮PBD累计5.594 ms（47.05%），局部润滑2.981 ms（25.08%）；场＋响应0.342 ms，一次力0.182 ms，二次力/有序求和0.538 ms，CFD两次查询0.246 ms。其他包括分量平衡、墙、边界、接受和调度。

**这是逐活动 CUDA Event 跨度，不是 CUPTI 纯 kernel 时长。**插桩与无Graph调度会改变开销，不能把百分比当作无扰动硬件占用分解。没有 Nsight/CUPTI 纯 kernel 记录，字段为 null；未估计补齐。CUDA Event覆盖整段也可能含主机空档，与CPU墙钟分别保存。用途和API核对来自 [NVIDIA Warp profiling](https://nvidia.github.io/warp/latest/user_guide/execution_and_performance/profiling.html)，并核对服务器安装版函数源码；没有安装/升级驱动或 Warp。

同一100步短对照，Graph墙钟59.628 ms、无Graph60.207 ms，实际位置逐位一致。旧 Graph 已正确使用，没有把它列为F10C新发明；该规模未测到明显额外收益。图初始化约15.46 ms；静态输入约0.610 s。插桩结果与独立非插桩对照各自存档。

完整批量成本还包括 CPU 分析/输出：共享负载下 B64 冷运行积分/质量约0.741 s、读回0.207 s、形态/诊断准备7.839 s、HDF50.999 s。其他CPU作业也会干扰这些值；但这份真实观测说明只优化GPU场查询不会自动按同倍数提升完整数据吞吐。
