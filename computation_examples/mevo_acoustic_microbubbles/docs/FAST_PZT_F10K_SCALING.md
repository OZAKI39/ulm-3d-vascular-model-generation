# F10K B2 固定状态规模测试

本测试在 RTX 4090 / Ryzen 9 7950X3D 上测量 **B=1 的单个 N 泡接触问题**，不代表 B 条独立轨迹并行或真实千泡运动。实际科学执行提交 `8e1e9aaec50fd11f5716051e7c301c19da31fdca`；完整数据 `results/fast_pzt/f10k/scaling_v3/`，汇总及独立核对 `analysis/SCALING.json`。

## 实际结果

每个方法、每个已执行规模仅 1 次预热和 2 次正式计时。表为两个正式完整求解的中位数，共 18 次实际求解，全部质量通过后才计算速度比。

| N | 状态来源 | 初始活动接触对 | CPU 完整 ms | GPU 完整 ms | CPU/GPU | 状态 |
|---:|---|---:|---:|---:|---:|---|
| 32 | F10J 真实状态 | 36 | 13.47185 | 24.16758 | 0.5574 | 两端 PASS |
| 128 | 单一连通合成网络 | 302 | 151.31304 | 17.33177 | 8.7304 | 两端 PASS |
| 512 | 单一连通合成网络 | 1344 | 2028.31959 | 97.67968 | 20.7650 | 两端 PASS |
| 1024 | 未初始化 | — | — | — | — | NOT_RUN / STATIC_MEMORY_BUDGET |

N=32 仍无 GPU 优势；128 和 512 在实际合格固定状态中反超。但不能据此确定一个普适的规模交叉点：真实 32 泡几何不规则，基础 PCG 用 132 次；128 合成格点用 21 次；512 完整对称 8³ 格点仅用 4 次。不同规模的几何及迭代难度不同，只有两个正式重复，也没有测量真实不规则大型团。

所有 N>32 均明确 `BENCHMARK_ONLY_SYNTHETIC_STATE`。用确定性单一立方格点、球径相同 R=1.78 µm、间距 1.999R、初始重叠 1.78 nm；自由速度为 −1 s⁻¹×(x−质心)，外力为 Stokes 阻力系数乘该速度，形成受压接触。不是多个互不作用的 32 泡复制块。保存每泡度数、活动对列表、重叠分布、坐标、驱动力及输入 SHA。CPU/GPU 读取同一数组，原接触刚度、局部润滑方程和算法不变。

## 数值精度与公平口径

CPU 仍是原几何非线性参考，内部 1e−15 m 容差保证参考准确性；GPU 保留 F10J PCG true+recursive 判据、相对 1e−12/绝对 1e−14、上限 256 次、24 次外迭代/20 次线搜索。最终两端使用相同 1e−14 m 保守梯度界及实际位移方程残差要求、17.8 nm 最大重叠、178 nm 单次修正，未降低质量来获得时间。

| N | 最大 CPU/GPU 位置差 m | 最大接触力差 N | 最终 GPU 基础/最后方向 PCG | 最大重叠 nm |
|---:|---:|---:|---:|---:|
| 32 | 2.295e−19 | 1.533e−20 | 132 / 93 | 17.4976 |
| 128 | 7.555e−21 | 1.596e−22 | 21 / 21 | 1.6883 |
| 512 | 2.934e−21 | 1.487e−22 | 4 / 4 | 1.6900 |

最终接触集合完全一致；每次调用都保存实际残差、线性残差、单边性、重叠、单次修正、迭代和质量，最后一对调用保存完整 CPU/GPU 坐标、力、活动对 NPZ。预热及第一次正式调用有完整诊断度量而非重复存全部向量。N=32 三次 GPU 调用与 F10J 原结果逐位一致，默认 32 泡限制仍保留。质量复核由 `analyze_scaling.py` 读取原始 18 次测量执行。

CPU、GPU 完整时间均包含各自状态准备、求解、实际残差/质量审计、相同字段 JSON 序列化；CPU 每次构建原 A/B，GPU 每次准备同一问题及回传必要证据。共同输入加载、独立参考 A、复用缓冲/Graph 构建和磁盘归档不放入每次驻留求解，单独计入完整阶段。CPU 真实 OpenBLAS 线程数为 1（NumPy 0.3.29、SciPy 0.3.28 库各一线程）；与原单线程配置一致，无额外多线程测试。

GPU 数据准备、驻留、同步、最终传回、JSON 和质量分别记录在 `MEASUREMENTS.json`。第一正式调用的中途标量读取次数 32/128/512 分别为 12/8/4，等待墙钟约 21.57/12.19/19.82 ms；这些等待包含正在运行的求解计算，不能当作可全部消掉的纯通信时间。32 泡小矩阵运算无法摊薄 PCG 启动、主机线搜索及同步成本；512 的完整质量检查又占用较大部分时间。CUDA event span 包括主机决策间隙，不是纯 kernel 性能或 Nsight 实测。

## 真实预算、内存与停止边界

- 求解与必要预热累计 **7.444138 s / 120 s**。
- 含缓冲分配、必要 Graph、共同输入与输出的完整阶段 **10.040085 s / 300 s**；Supervisor 子进程全过程 **10.218247 s**。
- 两个缺包启动失败另计 **0.410328 s**，没有科学求解；保留 stderr 和不可变提交。不把失败时间算成成功吞吐。
- 缓冲与 Graph 总构建墙钟 32/128/512 约 **0.117/0.125/0.157 s**，首次编译缓存及分项见 `CONSTRUCTION.json`，不声称清空缓存后的编译基准。
- 单次最大完整求解约 **2.03 s**；每个规模进程有 10 s watchdog，没有触发实际超时。N512 的三次 CPU 和三次 GPU 含构建约 7.19 s，未扩大重复数。
- N512 进程峰值 RSS 约 **3.49 GiB**（控制器采样最大 3747323904 bytes；进程自身 ru_maxrss 3744436224 bytes）。GPU 进程采样峰值 **418 MiB**，0.5 s 采样，包含 CUDA context，可能漏掉短峰值；不冒充精确设备分配上界。

1024 档静态 CPU 数组预算为 **24.49997 GiB**，超过预登记 **4 GiB** 数组上限，因此没有初始化，也没有单独跑 GPU 然后推算速度比。GPU 数组估计约 212 MiB，在 2 GiB 上限内；停止不是 GPU 显存失败、不是数值发散，也不是服务器物理 RAM 用尽。CPU 原实现保存所有泡对的稠密 B，大小为 N(N−1)/2 ×3N，即 **O(N³) 存储**，包括远泡对零行。比较的是指定的历史 CPU 实现，不是最佳可能的 CPU 算法。1024 的静态估计不属于实测内存；未运行 1000 泡轨迹或可选 2048。

这些结果支持未来研究大型、单一连通、不规则泡团的 GPU B2，同时应先移除 CPU 参考的全泡对稠密存储浪费，再用有代表性的有限状态复核，不能将当前 8.73×/20.77× 直接当作科学生产收益。千泡的真实迭代、同步和轨迹质量尚未测定。此项工程工作不先于固定目标导航、持续分裂正例和物理适用范围，不启动 B64 软接触生产化。

## 参考与环境

B2 判断直接依据项目 F10G–F10J 实际源码和独立参考；本轮没有重新发明接触模型。工具文档参考 [Warp 1.18](https://nvidia.github.io/warp/1.18/)、[CUDA 编程指南](https://docs.nvidia.com/cuda/cuda-c-programming-guide/)、[Nsight Systems](https://docs.nvidia.com/nsight-systems/UserGuide/index.html)、[SciPy 线性代数](https://docs.scipy.org/doc/scipy/reference/linalg.html)、[NumPy](https://numpy.org/doc/stable/)。本轮网页访问前两项失败，后三项可读；未使用未读网页支撑新结论。在线 stable 文档版本不等于运行版本。

实际 Python 3.12.3、Warp 1.18.0+cu12、NumPy 2.2.6、SciPy 1.15.3，驱动 550.120 保持不变；只补装版本固定的 threadpoolctl 3.6.0。全部实际版本、CPU/GPU 信息和 Supervisor 状态见 `ENVIRONMENT.json`。未开展 Nsight 新追踪；所有性能结论来自保存的计时、同步、残差和资源采样。
