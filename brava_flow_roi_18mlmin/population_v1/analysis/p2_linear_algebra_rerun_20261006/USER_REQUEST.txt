# Codex 新一轮开发分析提示词
## 主题：P2/P1 线性代数内存解剖与低内存 PETSc 路线验证 —— 不改变科学离散，条件满足后最多运行 1 次 manufactured pipe GPU CFD

你现在继续开发当前 BraVa 3D 微泡持续灌注/轨迹项目。

上一轮已经确认：

- target manufactured pipe 与历史 BraVa 的真实 BC 均不进入 weak Dirichlet；
- mixed P2/P1 common-curved volume assembly 已通过 native gate；
- strong Dirichlet、prescribed Cauchy traction、BraVa natural-pressure Neumann 路径已通过；
- 完整 frozen V2 TET4→TET10 curved elevation 已通过全单元 Jacobian/边界/topology QA；
- P2 representation、P2 CPU sampler、Poiseuille exact-node representation 均已验证；
- P1/P1 production path 保持不变；
- **actual P2/P1 CFD 仍未运行**；
- 唯一当前 blocker 是：原固定线性求解路线 `8 MPI + PETSc CUDA Mat/Vec + ASM overlap=2 + CPU LU` 的 host-memory preflight 不安全。

当前报告给出的规划量：

```text
P1 independent unknowns         = 144,844
P2 independent unknowns         = 814,201
P2 native storage slots         = 1,037,320
P1 structural scalar NNZ        = 7,719,184
P2 structural scalar NNZ        = 111,793,312
P2 / P1 structural-NNZ ratio    ≈ 14.48253
cgroup total limit              ≈ 42.06 GiB
current plannable headroom      ≈ 31.42 GiB
```

历史原路线估计：
- RSS×structural NNZ ≈ 152.4 GiB
- RSS×independent DOF ≈ 59.2 GiB
- inherited LU fill + observed ASM overlap，仅 value/index arrays ≈ 49.8 GiB
- deliberately removing overlap 的敏感性对照 ≈ 26.55 GiB

这些是估计，不是实测 P2 峰值，也不是数学下界。

本轮唯一主目标：

> **在完全保持 P2 velocity / P1 pressure 离散、BC、stabilization、时间步、非线性容差和物理模型不变的前提下，找出原线性代数路线的真实内存瓶颈，并判断能否用现有成熟 PETSc 功能把 P2 manufactured pipe 安全压进当前 cgroup。**

本轮允许改变的只包括：
- algebraic numbering / storage（若证明确有冗余且可局部修复）；
- PETSc preconditioner / KSP 实现；
- MPI/ASM 配置，但必须受控验证解等价性。

本轮禁止把线性求解器调整写成“新的 CFD 物理模型”。

最终只能回答：

`P2_PIPE_LINEAR_ALGEBRA_FEASIBLE = YES / NO / NOT_EVALUABLE`

并且只有 YES 时，才允许最多启动 **1 次** P2/P1 manufactured pipe GPU CFD。

# 3. Phase A —— 精确解剖 mixed P2/P1 algebraic storage

必须回答为什么：

```text
independent unknowns = 814,201
native storage slots = 1,037,320
差值 = 223,119
```

而 223,119 与 unique P2 edge count 相同。

逐层审计：

```text
mesh DOF
→ field DOF
→ local equation slots
→ global equation numbering
→ PETSc row/column numbering
→ block preallocation
→ constrained/unused pressure-edge slots
```

必须区分：

1. 真正独立 unknown
2. storage-only slot
3. constrained slot
4. structurally allocated but numerically zero entry
5. actual nonzero matrix entry

输出至少：

`P2_DOF_STORAGE_AUDIT.json`
`P2_DOF_STORAGE_AUDIT_ZH.md`

必须给出：
- velocity corner DOFs
- velocity edge DOFs
- pressure corner DOFs
- edge pressure slots
- total equation rows
- active rows
- constrained rows
- PETSc block size
- scalar vs block NNZ

### Phantom-pressure structural cost

量化：

> 如果只保留数学上的 `3*N_P2_velocity_nodes + N_P1_pressure_nodes`，理论 graph 比当前 `4*N_P2_nodes` 少多少 rows / structural scalar NNZ / block entries？

不要立刻改代码。
先输出一个**compact mixed graph reference**。

输出：

`COMPACT_MIXED_GRAPH_REFERENCE.npz`
`COMPACT_MIXED_GRAPH_STATS.json`

### Stop A
如果 223,119 差值不是 pressure-edge slots，或无法建立可信 mapping：

`MIXED_STORAGE_ROOT_CAUSE_NOT_ESTABLISHED`

不要实现 compact numbering。
继续只做 preconditioner memory audit。

# 6. Phase D —— 审计 PETSc 中现成的低内存候选，不自研求解器

先读取当前 PETSc build 实际支持的 PC/KSP/package。

只允许从**已有成熟 PETSc 功能**中筛候选。

重点检查但不预设一定可用：

1. **ASM overlap 0 或 1 + 现有 local factorization**
2. **field-split Schur complement**：
   - velocity field
   - pressure field
   - PETSc `PCFIELDSPLIT`
3. velocity block 使用已有：
   - GAMG
   - HYPRE/BoomerAMG（只有实际build有）
   - other installed AMG
4. pressure Schur approximation：
   - 只使用现有/文献标准且能由当前矩阵构造的形式
   - 不自创经验压力算子

不要同时测试十个PC。

静态审计后，最多选择 **2 个候选**进入下一阶段。

选择规则必须在运行前写入：

`LINEAR_SOLVER_CANDIDATE_PLAN.json`

选择依据：
- 预计内存
- 当前build可用性
- 对saddle-point系统的适用性
- 实现改动大小
- GPU/CPU兼容

# 7. Phase E —— 先在 P1 已知系统上验证“只改变线性代数，不改变解”

这是必须的回归门。

不能先拿 P2 当实验场调 solver。

优先复用一个已有 P1 manufactured pipe checkpoint / saved state，运行最小受控段：
- 同一 residual / Jacobian
- 同一 nonlinear tolerance
- 同一 linear tolerance

对于 baseline PC 和最多2个候选，比较：
- linear convergence
- nonlinear convergence
- final state difference
- velocity/pressure max difference
- Q / dpdz
- residual norm
- wall time
- peak RSS
- GPU memory

候选只有在：
- 解在 solver tolerance / roundoff合理范围内一致；
- 没有改变 scientific configuration；
- convergence不恶化到不可接受；

时才能进入 P2。

输出：

`P1_LINEAR_SOLVER_PARITY.json`

### Stop E
如果没有候选能在 P1 保持解一致并稳定收敛：

`NO_SAFE_LOW_MEMORY_LINEAR_SOLVER_CANDIDATE`

停止，不跑 P2 CFD。

# 9. Phase G —— compact mixed numbering 只在明确高收益时允许 prototype

不要默认重构 equation numbering。

只有当 Phase A/B 证明：
- pressure-edge phantom slots 对 structural NNZ / memory 有显著贡献；
- 现有 low-memory PC 仍不能提供安全余量；
- compact numbering 可以局部实现，不要求重写全solver；

才允许 validation-only prototype。

预声明收益门：

若理论/实测显示 compact numbering 对峰值内存预计改善 <15%，不实现。

若 >=15%，允许做：
- isolated numbering/graph prototype
- local/global index validation
- matrix assembly regression

本轮**不要求**把 compact numbering 变成production feature。

任何 prototype 必须：
- P1 numbering unchanged
- P2 mathematical DOFs unchanged
- matrix/residual equivalent
- no physics change

输出：

`COMPACT_MIXED_NUMBERING_PROTOTYPE.json`
