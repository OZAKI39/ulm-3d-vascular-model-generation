# 0. 本轮总体目标

项目最终希望利用四路 PZT 超声实现微泡群的聚集、移动、形状保持与形变控制。

但本轮暂时不执行声学控制。

当前最直接的目标是建立：

**实时相机画面 → 全通道可见单泡 → 单泡群体运动趋势 → 微泡聚集趋势 → 可见泡团形成与形态变化 → 实时状态显示与记录。**

本轮必须支持两种正式输入模式。

### LIVE_CAMERA

真实 Chronos 相机接收模式。

在实验室使用现有 `CHRONOS_control` 接收器获取画面，实时传递到视觉观测系统。

本轮由于相机不可连接，只实现接口和模拟验证，不得宣称真实在线测试已经通过。

### REALTIME_REPLAY

真实录像模拟实时输入模式。

使用：

`/home/lzy/projects/external_connect/sample_videos/Recording 2026-10-15 185901 截取视频.mp4`

按照录制文件的真实 PTS 时间间隔向同一视觉系统发送帧。

该模式必须模拟持续接收、有限队列、处理延迟、丢帧、旧帧过期、停止与恢复等行为。

**LIVE_CAMERA 和 REALTIME_REPLAY 必须经过同一套标准化帧接口和核心分析流水线。**

不得开发两套逻辑不同的视觉系统。

# 2. 重要设计原则：实时观测优先，单泡精确跟踪不是目标

用户当前真正关心的是：

**PZT-OFF 时，看清可见分散微泡的整体运动趋势。**

**PZT-ON 时，观察微泡是否出现向某些区域靠近、逐渐聚集并形成可见泡团的趋势。**

因此：

不要求对每颗分散微泡进行高精度亚像素定位。

不要求长期维持单泡 ID。

不要求所有单泡都有六参数。

不要求整个通道每个窗口都具备可信速度。

不需要当前立即训练复杂 AI 模型。

需要的是：

1. 全通道持续发现可见单泡；
2. 可靠输出单泡候选位置和空间分布；
3. 在有足够运动证据的区域估计局部移动方向；
4. 描述候选单泡的靠近、分散和局部汇聚趋势；
5. 检测可见聚集区域形成与变化；
6. 如果形成可观测泡团，进一步统计其形状和整体运动；
7. 对不能可靠判断的情形明确拒判。

所有聚集指标首先表示二维可见微泡分布变化。

不得把图像重叠、局部密度增大或点云连通直接当成真实物理接触、融合或三维聚集的证明。

# 6. 实时计算架构：解码、分析、显示分离

这是本轮最重要的工程任务之一。

F10X 正式完整回放 p95 约 71.43 ms，新鲜有效群体状态约 10.42 Hz。

本轮应优先改善系统架构和新鲜状态，而不是继续重写 FFT。

建议采用多个独立模块：

**A. Frame Acquisition**

持续获取最新相机或视频帧。

**B. Observation Worker**

执行全通道检测、局部运动与聚集趋势分析。

**C. State Publisher**

将可信状态发送给本地消费者。

**D. Visualization**

实时显示原始画面、微泡候选、运动场和聚集趋势。

**E. Recorder**

异步保存状态、必要诊断数据和可选视频。

这些模块不能互相无限阻塞。

## 6.1 有界队列

使用成熟线程／进程通信工具。

实时观测优先使用最新帧机制或小容量有界队列。

当分析赶不上输入时，可以丢弃过期帧，但必须记录：

- 源端解码数；
- 桥接接收数；
- 桥接覆盖数；
- 分析跳过数；
- 实际分析数；
- 有效状态数；
- UI 跳过数；
- 录制丢弃数。

这些数量不能混为同一种“丢帧”。

实时模式允许跳过处理帧；离线完整分析仍应具备处理全部帧的能力。

## 6.2 独立显示与数据保存

正式运动状态不应等待：

- Matplotlib 绘图；
- PNG 保存；
- MP4 编码；
- 大量 JSON 格式化；
- 全帧 debug 数据写盘。

科研绘图和大量文件保存应由后台工作器完成，或在实验结束后离线生成。

正式推理主线应优先输出轻量状态对象。

但不能在 profiling 前就断言绘图与保存是当前最大瓶颈。

必须逐阶段测量并证明优化收益。

## 6.3 新鲜度与异常处理

必须复用现有 stale/TTL 思想。

发生以下情况时：

- 视频没有新帧；
- PTS 断裂；
- 会话重新连接；
- 图像质量明显不足；
- 上游停止；
- 结果超过可配置时效门槛；

下游不能继续显示旧六参数或旧聚集趋势为当前有效状态。

允许界面保留最后一张画面作为诊断，但必须覆盖醒目的 STALE 或 DISCONNECTED 标识。

正式状态消息必须无效化。

# 7. 全通道可见单泡观测

## 7.1 原则

每个实际进入分析的帧都需要在有效 PDMS 通道中检查可见微泡。

优先复用 F10X 通道遮罩和原 OpenCV 检测器。

注意：F10X 的通道 mask 来自 1476×1120 录像。

历史 Chronos 监看流可能为 1280×1024。

两者不能仅通过图像尺寸相同或简单缩放，就认定通道几何自动正确。

必须为不同视频源保留独立的几何配置，或执行经核查的配准。

如果新 LIVE 源的通道遮罩尚未验证，应显式提示用户在界面上核查或调整。

不可使用错误遮罩生成看似有效的结果。

## 7.2 单泡候选

每帧输出：

- 可见候选中心；
- 候选数量；
- 候选空间分布；
- 质量分数；
- 边界附近候选；
- 可能失焦或低质量区域；
- 当前观测范围。

不要求单泡长期 ID。

不要求单泡精确轮廓。

不强制检测所有人眼都无法可靠区分的暗微泡。

优先定义并验证对“实验需要观察的可见微泡”的检测表现。

可以复用 F10T 已保存的人工审核数据。

人工未审核区域不能自动当作真实负例。

# 8. 单泡群体运动趋势分析

目标不是精确追踪每一颗泡，而是提供足够可靠的整体运动方向和局部相对运动信息。

## 8.1 保留 PIV

继续使用 F10X 当前成熟的 CuPy GPU-PIV 作为主力运动估计。

Rust OpenPIV 保留为参考和备用。

必须区分：

- 全通道可见微泡检测；
- PIV 可计算区域；
- PIV 有效向量区域。

即使某个窗口计算了 PIV，也不代表该速度有效。

## 8.2 输出运动趋势

至少包括：

- 局部平均运动方向；
- 局部表观速度；
- 运动方向的一致性；
- 不同区域的运动差异；
- 局部朝某个中心汇聚或远离的趋势；
- 运动场有效支持；
- 运动状态年龄。

不要因为某个分散单泡无法建立长期对应，就使整个系统无法输出分布或其他有效群体信息。

## 8.3 OT 辅助

可以复用 F10W 的 Unbalanced OT：

https://github.com/PythonOT/POT

在候选较稀疏、PIV 支持不足的局部区域，进行有界集合运动对照。

但 OT 的软对应不能冒充经过验证的单泡真实身份。

本轮不必再次大量搜索预训练 AI 模型。

# 9. 核心新模块：微泡聚集趋势观测

这是本轮必须真正开发的科研新功能。

## 9.1 研究目标

希望系统能够连续回答：

- 微泡是否逐渐向某个区域靠近？
- 某个局部区域的可见密度是否增加？
- 分散微泡的空间范围是否缩小？
- 是否形成了相对稳定的可见聚集区域？
- 某些微泡是否正在接近已存在的群体？
- 聚集区域形成之后是否发生伸展、收缩、旋转或分散？

不要求此阶段判定真实三维物理融合。

## 9.2 优先复用成熟数学和开源算法

使用已有：

- NumPy；
- SciPy；
- OpenCV；
- scikit-learn；
- F10U/F10X 分布和几何模块。

官方资源：

https://numpy.org/

https://scipy.org/

https://scikit-learn.org/

https://opencv.org/

必要时使用：

- cKDTree；
- DBSCAN；
- 最近邻距离统计；
- 局部密度估计；
- 候选图结构；
- 已有 OT 软匹配；
- PIV 局部运动场。

不要为此训练大型网络，也不从零开发通用聚类算法。

## 9.3 聚集趋势指标

至少研究以下连续指标。

**A. 局部可见密度**

\[
\rho(x,y,t)
\]

记录不同区域微泡候选密度随时间的变化。

**B. 最近邻距离**

统计微泡候选之间的最近邻或 k 近邻距离分布。

距离减小可以支持二维可见点靠近的趋势，但需考虑可见数量变化和检测误差。

**C. 回转半径**

\[
R_g(t)
\]

在具有可比空间支持的局部候选群中描述分布范围。

不能因微泡消失或进入视野造成的 Rg 改变，直接宣称真实群体收缩。

**D. 局部汇聚运动**

使用可靠 PIV 或短时对应，研究速度是否向某个局部参考中心汇聚。

可以用径向速度趋势、相对位移和局部二维散度辅助分析。

**E. 可见聚集区域**

使用局部密度和空间连接结构寻找候选聚集区域。

记录：

- 候选区域数量；
- 区域中心；
- 空间范围；
- 有效候选数；
- 回转半径；
- 方向；
- 形状变化；
- 相对稳定性。

如果还没有足够证据表明形成独立泡团，必须保留为候选区域，不可强制给出真实泡团身份。

## 9.4 重要的时间序列设计

不能只比较两帧的微泡数量。

需要研究一段时间中的分布与运动变化，并防止：

- 视野边界进出；
- 失焦；
- 可见数量改变；
- 手动注射产生的整体漂移；
- 密集重叠造成的候选合并；
- 照明变化；

被误判为真实聚集。

必须分别输出：

`visible_distribution_change`

`local_convergence_evidence`

`aggregation_trend_status`

`observation_quality`

这些名称可以根据现有 Schema 适当调整。

不要输出未经标定的“物理聚集概率”。

如数据证据不足，使用 `NOT_OBSERVABLE` 或明确原因。

# 12. 性能优化与目标

## 12.1 优先级

**第一优先：实际接收画面稳定、新鲜，不被后端计算阻塞。**

**第二优先：可见单泡和聚集趋势有足够可靠的观测更新。**

**第三优先：在上述条件下提高实时性能。**

不能通过简单减少有效观测来制造更高 FPS。

## 12.2 性能目标

对于当前约 30 fps 录像：

争取在 1.0× 实时回放时连续运行，画面稳定，积压有界，状态及时失效，并提高有效趋势更新频率。

目标完整处理 p95 尽量低于约 33.3 ms，但不将其当成未经测试的保证。

对于实验室约 60 fps 监看流：

需要进一步检查约 16.7 ms 输入周期下的系统行为。

允许采用分层频率：

- 图像接收持续运行；
- 全通道候选扫描尽量跟随输入；
- 局部高成本 PIV 按有效资源更新；
- 聚集趋势按新鲜有效数据更新；
- UI 使用合理显示刷新频率。

所有层的实际频率必须分别记录。

如果 60 fps 下无法处理每一帧，也要保持最新帧和正确的丢帧统计。

不能让消费者越处理越落后于当前场景。

## 12.3 性能优化任务

先进行 profiling，定位：

- 解码；
- 桥接；
- 图像复制；
- 全通道检测；
- GPU PIV；
- 局部群体分析；
- 聚集指标；
- 序列化；
- UI 渲染；
- 文件保存。

然后实施有证据支持的优化。

优先避免：

- 每帧重复建立 CUDA 环境；
- 重复 GPU 数据上传下载；
- CPU/GPU 多次不必要同步；
- 每帧重建固定遮罩；
- 热路径中构造大量嵌套 Python 对象；
- 每帧阻塞式写入 PNG/MP4；
- 消费者获取无限积压的旧帧。

充分利用已有计算服务器 CPU/GPU。

但不能为提高利用率而进行无意义压力测试。
