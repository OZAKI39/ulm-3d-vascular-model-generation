# PZT 状态与实验模型

## 使用方法

1. Windows 打开 `F:\Tektronix_control\start_gui.cmd`，保持该窗口运行；只运行一个 AFG 控制器。
2. 启动观测界面，右侧选择 **PZT status / layout**：

   ```bash
   bash /home/lzy/projects/external_connect/vision_tracking_research/realtime_collective_observation_v1/start_live.sh
   ```

3. 点击 **Read PZT status**，由 Windows 控制器重新查询全部四路。尚未连接时会先进行只读连接，按钮显示 **Reading…**，收到本次查询完成回执才提示更新成功。连接或读取失败会显示实际失败状态；超时不会把旧值当成新读数。
4. 点击 **PZT connections**。沿实际电缆核对四个输出，各自在 **Connected PZT** 下选择 **X− / X+ / Y− / Y+**，然后点击 **Save connections**。不确定的行保留 **Unassigned**。

界面、图像周围、曲线区和俯视图背景均为黑色。每次启动自动加载上一次点击 **Save connections** 保存的空间对应关系，不需要重新选择；启动、读取状态和关闭界面均不会重置该文件。

你只需要确认信号发生器通道接到哪枚实体 PZT，不需要输入几何坐标。不得将两路分配给同一枚 PZT；重复选择会提示并阻止保存。部分确认也可以保存，其他位置继续保持未分配。取消窗口不修改已保存关系。

## 固定实验模型

俯视图复用当前 F10M-R3 装置几何，原点在 PDMS 中心，+X 向右、+Y 向上。四枚 PZT 直径均为 **7 mm**，朝向装置内部。

| 实体 PZT | 中心 X/Y/Z（mm） | 发声朝向 |
|---|---|---|
| X− | −16.25 / 0 / 0 | +X |
| X+ | +16.25 / 0 / 0 | −X |
| Y− | 0 / −4.5 / 0 | +Y |
| Y+ | 0 / +4.5 / 0 | −Y |

图中显示 32.5 × 9 mm 的 PDMS 俯视轮廓、直径 1.6 mm 的中央通道、封闭 X 端，以及两个直径 1.5 mm 的顶部开口。顶部孔中心沿用原模型的 X=±10.85 mm；5.4 mm 定位参考仍保留原记录中的测量参考限制。

银灰短条表示竖直 PZT 圆片的俯视投影，箭头表示发声面朝向。XY 使用同一比例，位置不会随信号发生器通道选择而移动。此图是装置布局，不是声场，也尚未与相机图像配准。

## 通道与参数

| 本界面通道 | 设备 USB 序列号 | 原 Windows 控制器标签 |
|---|---|---|
| A/CH1 | 2147075 | PZT1 |
| A/CH2 | 2147075 | PZT2 |
| B/CH1 | 2439003 | PZT3 |
| B/CH2 | 2439003 | PZT4 |

原控制器中的 PZT1–4 是输出通道标签，不能直接当作 X±、Y± 的物理位置。新界面按用户保存的对应关系，把实际读回状态显示到相应实体 PZT 上；同时检查设备别名、USB 序列号和 CH，不依赖枚举顺序。

卡片显示连接状态、实际 ON/OFF、频率（MHz）、幅值（Vpp）、相位（度）、波形和模式。SIN 为正弦波，SQU 为方波，CW 为固定频率。读数时间、当前参数及错误信息放在鼠标悬停提示中，避免挤占主界面。为加快刷新，后台仅查询上述显示所需的七项读数；负载、偏置、调制及扫频/突发详细参数仍可在 Windows 控制器的 **Read Instrument Status** 中完整读取。

自动监视在一路读完后尽快读取下一路；本机两台 AFG1062 实测每路约 **0.94 秒**更新一次（优化前约 **4.02 秒**），超过 8 秒仍按原规则失效。控制操作优先于下一次后台读取，正在执行的单路查询仍可能带来约 0.24 秒等待。手动 **Read PZT status** 请求会使用原 Windows 控制器的同一个 USB 工作队列，新读取四路而非仅刷新缓存。状态读取采用已验证的逐条查询方式；原控制操作保持其已有协议。查询超时会保留驱动的会话错误保护，不尝试把迟到回包当作有效数据。读失败或身份不符显示 UNKNOWN，不沿用旧参数。**Vpp 是发生器读回值，不是声压 Pa；ON 不证明实际 PZT 电缆接通或已经发声。** 用户的通道对应选择是人工接线记录，不是硬件检测结果。

相机 Start/Stop 只处理观测和录像；PZT 输出继续由原 Windows AFG 控制器操作。观测界面通过文件发送仅允许 `READ_STATUS` 的读取请求，并消费与请求 ID 对应的回执；不发送硬件控制命令、不另开 VISA 会话。过期请求、旧控制器会话的请求、其他操作指令不会被执行。

## 保存与复现

- `configs/pzt_experiment_model.json`：从当前实验模型提取的几何及原始文件 SHA-256。
- `configs/pzt_layout.json`：用户确认的通道对应关系，重启后保留。
- `src/pzt_status.py`：身份校验、过期处理和映射验证。
- `src/pzt_panel.py`：简洁英文状态卡、固定俯视图和连接设置。
- `evidence/pzt_model_mapping_20261019/`：旧布局备份、测试和截图。带 `fixture_not_actual_wiring` 的截图仅验证映射显示，不代表实际接线，也没有写入用户配置。

旧版手填坐标已备份；不会据此自动猜测接线。几何与通道映射的修改不影响发生器配置。

2026-10-19 刷新优化实机验证：单路七项显示读数约 242 ms，完整参数读取约 576 ms，20 组对照读数全部一致。已连接状态下点击 **Read PZT status**，四路读取并返回界面约 1.39 秒；连续监视记录 53 次更新，每路间隔 0.927–0.967 秒。设备设置前后相同，四路均 OFF，保存的通道映射 SHA-256 未变。测试在未启动相机处理时进行；这些是本机实测时间，不是硬实时期限或从点击到实际声学输出的延迟。首次连接还需要设备枚举时间，本次未重测冷连接；优化前的 4.98 秒冷连接结果不能直接与上述已连接读取比较。

状态文件在独立线程每 40 ms 检查一次，仅文件变化时解析；界面每 50 ms 获取最新状态，只重绘变化的文字和布局状态。验证脚本、前后代码差异、实际读数、时间记录与截图位于 `evidence/pzt_latency_20261019/`。

## 将 PZT 信息录入实验视频

照常点击 **Start → Stop**；保存完成后点击 **Open records**，打开 `experiment_overlay.mp4`。左侧为相机画面与识别结果，右侧为黑底 PZT 参数卡和俯视布局，包括四路对应关系、ON/OFF、频率、Vpp、相位、波形/模式及读回年龄。原始 `experiment_raw.mp4` 仍保留相机原尺寸。

逐帧 `video_frames.jsonl` 中的 `pzt_sample_id` 对应 `pzt_readbacks.jsonl` 中同名 ID；后者保存读回原值、身份、时间和通道映射。`pzt_frame_unix_s` 用于按该帧时刻判断读数是否过期，`pzt_experiment_model.json` 保存本次布局几何。可据此分析微泡运动与发生器状态的关系。

录像使用帧抵达前已经获取的最近读回，不使用后来的状态修饰过去画面；读回不是曝光同步数据，ON 仍不等于实际声压检测。回放没有配套 PZT 历史的旧视频时显示 NOT RECORDED。断连、读取失败、超时和未分配的通道也会保留其真实状态。

2026-10-19 录像验证：真实预览收到的 11 帧全部写入，原始/叠加视频 PTS 一致，没有使用未来 PZT 读回；30 项相关测试通过。额外以已录图像验证 30 帧/秒编码，90 帧全部写入，无编码丢帧。此项是编码测试，不代表相机接收或识别速率。代码、试录、逐帧证据和截图见 `evidence/pzt_video_20261019/`。
