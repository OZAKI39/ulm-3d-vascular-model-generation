# 0. 本轮核心目标

目前项目已完成 F10W，包含完整 937 帧 Chronos 原始录像的历史 ROI PIV、开源预训练模型比较以及科研图表和视频。

F10W 表明，现阶段还没有学习型模型能够在真实显微运动的可靠性、有效输出率和时效性方面全面替代 PIV。

因此，本轮不再训练新的 CNN、光流网络或世界模型，而是将现有 PIV 发展为适合整条 PDMS 通道的高性能观测系统。

本轮必须解决五个问题：

1. **观测范围扩大**：从原来固定的小 ROI 扩展至整个有效 PDMS 通道，能够持续发现通道各位置的可见微泡。
2. **计算加速**：优先利用成熟开源 Rust、CPU 多核、PyTorch GPU 或 CuPy PIV 实现，在相同服务器上比较真实效率。
3. **计算资源自适应分配**：全通道每帧快速观察，只在具有足够运动证据的窗口进行高成本 PIV；支持多速率局部更新。
4. **精度和可信度改进**：针对固定 PDMS 纹理、墙边、低密度微泡、漏检、背景变化等条件，改进 PIV 预处理、局部向量验证与拒判。
5. **分层群体运动状态**：输出全通道局部运动场及其有效性，并对能够合理界定的局部可见微泡群分别输出六参数运动。

必须明确：

**全通道观测不代表所有像素都能测得真实流速。**

没有可靠示踪运动证据的区域必须标记不可观测，不得填充零速度、插值结果或虚构水流。

# 5. 全 PDMS 通道几何遮罩

这是扩大观测范围的第一项核心工作。

## 5.1 从真实视频建立通道区域

原始视频约为 1476×1120。

使用完整原始帧确定：

- PDMS 通道位置；
- 通道内部可观察区域；
- 通道壁；
- 不属于流道的固定结构；
- 需要排除的边缘。

优先使用已有 OpenCV 多边形与掩码工具。

可以基于真实图像提供半自动初始多边形，但必须保存可视化检查结果。

若边界存在不确定性，提供可编辑的多边形文件或简单标注入口，不要把自动生成边界直接声明为准确真值。

建议文件：

`channel_mask.json`

`channel_mask.png`

`channel_geometry_audit.md`

## 5.2 墙边安全剔除

墙面强反射可能影响 PIV 相关峰。

不能简单把窗口中心落在通道内部，就认为整个 PIV interrogation window 有效。

应检查窗口实际覆盖的像素是否跨越墙面或无效区域。

可以采用与窗口大小相关的掩码内缩、有效像素比例检查或已有动态 masking。

墙边剔除宽度必须记录，并根据真实图像和 PIV 窗口尺寸确定。

需要比较不同剔除规则下：

- 有效面积；
- 误测风险；
- 靠壁区域速度偏差；
- 计算时间。

不得为了提高覆盖率而把固定墙体纹理纳入微泡运动场。

## 5.3 固定遮罩的有效条件

静态遮罩只有在相机、芯片和成像视野相对稳定时有效。

如果存在载物台移动、相机平移或通道位置变化，必须检测配准失效，并重新计算或拒绝使用旧遮罩。

不能将位置变化后的旧遮罩默认为有效。

# 6. 全通道快速观察与活动窗口筛选

## 6.1 每帧覆盖整个通道

核心要求：

**每一帧都必须扫描整个有效通道，判断哪些区域存在可见微泡或其他可能的运动证据。**

不能仅围绕之前已经发现的某一个泡群持续观察。

新出现的微泡、稀疏微泡及远离原 ROI 的运动都需要有被发现的机会。

优先复用已有 OpenCV 检测器、背景差分、局部纹理统计、积分图和成熟的区域筛选方法。

## 6.2 两级计算架构

第一层：快速全通道观察。

输入当前图像，输出：

- 微泡候选位置；
- 局部候选密度；
- 活动窗口候选；
- 局部纹理支持；
- 成像质量；
- 低支持区域；
- 未观测原因。

第二层：局部精细 PIV。

只在满足预先定义的有效观测条件的窗口内，执行完整相关计算。

注意：

快速筛选必须保留发现新微泡的能力。不能因为某一位置连续几帧没有运动，就永久停止检查该区域。

应设计周期性的完整复查或其他明确的重新激活机制。

## 6.3 筛选质量必须单独验证

需要测试：

- 稀疏微泡是否被漏掉；
- 低对比度微泡是否被漏掉；
- 明亮 PDMS 纹理是否产生假活动；
- 新进入通道区域的微泡是否能被及时发现；
- 小位移是否被误判为静止；
- PZT-OFF 状态下的自然流动是否仍可被观察。

不能用活动窗口选择器自己的输出作为唯一真值。

如果人工确认的全通道候选真值不足，应建立少量审核样本，并明确验证覆盖范围。

## 6.4 GPU 活动窗口批处理

优先调用 TorchPIV 或 CuPy 已有计算内核。

对需要分析的窗口进行批量处理。

若现成 GPU-PIV 只能接收完整规则图像，可通过有限的裁剪、分块、合并适配解决；不得重新实现 FFT 互相关核心。

必须比较：

- 整通道规则网格批处理；
- 先筛选后批处理；
- CPU Rust；
- GPU TorchPIV；
- GPU CuPy。

如果稀疏筛选产生的调度开销抵消了计算节省，允许保留简单而更快的规则批处理方案。

所有跳过的局部窗口必须标记未测量，而不是有效零速度。

# 7. 自适应多速率观测

全通道每帧快速扫描。

精细 PIV 可以按区域优先级采用不同更新频率。

候选设计：

- 高密度或快速变化的活动区域：尽量每帧；
- 低活动区域：降低精细 PIV 更新频率；
- 新出现的目标：立即提高优先级；
- 失焦或无效区域：保留状态原因；
- 长时间低支持区域：定期重新检查。

例如研究 1、3、6 帧更新策略，但具体选择必须经验证，而不是固定把 3–6 帧设为正确答案。

必须输出：

- 每个窗口最后一次计算时间；
- 当前观测年龄；
- 实际更新周期；
- 是否为新鲜测量；
- 是否过期；
- 未观测原因。

**不能把上一时刻保存的速度场当成当前帧的新鲜速度场。**

可选地为可视化提供时间保持或插值效果，但必须标记：

`DISPLAY_ONLY_INTERPOLATION`

这些值不得冒充实际测量，也不得参与新鲜状态统计。

# 8. PIV 精度增强研究

这是与计算加速同等重要的科研任务。

## 8.1 背景处理对照

至少比较：

- 原始灰度；
- 当前 F10U 局部增强；
- 固定背景校正；
- 因果滑动背景模型；
- CLAHE 或局部对比度处理；
- 有明确价值时的其他成熟去噪方法。

使用 OpenCV 和 OpenPIV 已有实现。

时间中值背景需要区分：

**离线非因果背景**：可以使用未来帧，仅作离线诊断。

**实时因果背景**：只能使用当前与历史帧。

不能使用整段录像的未来信息来计算背景，再宣称在线算法拥有相同结果。

背景算法必须防止移动微泡形成静止残影，或被过度滤波消除。

所有预处理均保留原始灰度对照。

## 8.2 搜索范围

不要直接将搜索范围固定为 ±4 px。

应该根据实际帧间位移、PTS、预期最大运动、窗口大小和多遍策略研究合理的搜索区域。

若丢帧导致时间间隔变大，不能继续假设目标位移始终小于原有搜索半径。

可以采用已有的粗到细 PIV 和多尺度方法。

## 8.3 时间跨度

比较：

- 相邻帧；
- 间隔两帧；
- 间隔三帧；
- 必要时更长的因果跨度。

严格使用实际 PTS。

分别分析：

- 小位移精度；
- 较大位移；
- 突然变化；
- 参数噪声；
- 位移歧义；
- 有效率；
- 时间窗带来的固有观测延迟。

不能只因为长窗口曲线更平滑，就认为估计更准确。

## 8.4 多遍 PIV

直接复用 OpenPIV、TorchPIV 或 CuPy 中可用的多遍／窗口形变。

在相同图像和真值上比较：

- 单遍；
- 两遍；
- 粗到细；
- 不同窗口大小与重叠率。

多遍 PIV 可以作为离线精细参考，但必须检验其实际精度收益和计算成本。

## 8.5 相关峰与异常向量

复用成熟：

- SNR；
- peak-to-peak；
- 局部中值验证；
- 纹理支持；
- 相关峰歧义；
- 空间覆盖；
- 仿射拟合残差；
- 几何条件数。

注意已发表的 PIV 相关峰不确定性研究，例如：

Xue、Charonko、Vlachos，*Particle Image Velocimetry Correlation Signal-to-Noise Ratio Metrics and Measurement Uncertainty Quantification*, Measurement Science and Technology, 2014。

https://doi.org/10.1088/0957-0233/25/11/115301

允许研究相关峰质量到测量误差的校准，但不能仅凭一个 SNR 阈值就宣称获得校准好的 95% 置信区间。

插值和异常向量替换必须保留来源标识，不得把替换向量作为原始有效测量参与精度统计。

# 12. CPU/GPU 资源要求

你已掌握服务器连接方式。

首先实际检查：

- CPU 型号及核心；
- 内存；
- GPU 型号及数量；

注意避免：

- GPU 小任务频繁同步；

- GPU 与 CPU 任务互相争抢 I/O；
- 为了提高利用率进行无意义压力测试。
