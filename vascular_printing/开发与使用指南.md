# vascular_printing 开发与使用指南

> 核对日期：2026-09-28。本文依据当前源码、配置、输出清单和实际目录编写，供接手开发时查阅。它描述当前实现和已保存结果，不代表本次重新执行了全部建模或切片。

## 1. 这个项目在做什么

项目根目录是 `/home/lzy/projects/vascular_printing`。项目将脑血管数据转换为可供检查和打印的血管制造模型，当前主线使用 **BraVa 的 BG001 右侧大脑中动脉（RMCA）**。

BraVa 提供血管中心线、半径与连接关系；TopBrain 提供带人工解剖标签的参考样本。项目通过配准与多个参考样本的最近邻支持，将解剖信息迁移到 BraVa，再提取、修正和简化区域，生成血管表面、四个外接端口以及一体式 ABS 倒模件。

当前交付包括 candidate 0 和 candidate 15 两种打印姿态。其血管和盒体设计相同，摆放方向与切片支撑不同。数字模型和切片检查已有记录，实物打印、支撑拆除及灌注效果仍需实验验证。

**如果要继续开发 candidate 0、15 对应的 BraVa 血管 ROI，请先看 [第 7.1–7.6 节：对应 ROI 的完整开发链](#candidate-roi-development)。** 其中列出该 ROI 的身份、逐阶段输入输出、可视化方式以及重新计算时的衔接要求。

目录中也保留小鼠处理、早期人脑 ROI 和表面重建代码，它们不都是当前 BG001 打印主线的必经步骤。CFD 与流场求解仍属于旧工作区。

### 三类数据不能混淆

| 数据层 | 含义 | 使用时需要注意 |
|---|---|---|
| 原始几何与解剖参考 | BraVa 原始 SWC、ColorCoded 文件、TopBrain 原生标签 | 保留原始内容与许可；TopBrain 标签属于它自己的样本 |
| 迁移得到的语义 ROI | BraVa 上由参考样本支持的标签、边界及子树 | 是解剖迁移候选，不是 BraVa 自带的人工 M2/M3 真值 |
| 制造与打印几何 | 半径补偿、近端 context、四端口、框架或盒体 | 工程结构不等同于原始解剖；保留其与原始节点的映射 |

MINI、BALANCED、RICH 表示制造候选的范围与复杂度；candidate 0、15 表示最终倒模件的打印姿态。这两套编号没有一一对应关系。

## 2. 处理逻辑与当前采用的结果

```text
BraVa BG001.CNG.swc ────────────────────────┐
BraVa BG001_ColorCoded.CNG.swc → 主要动脉分类 ├→ BG001 MCA 几何
                                           │
TopBrain 图像 / 标签 / labelmap             │
    → 参考样本语义点缓存                     │
    → Open3D 相似变换配准 + 多参考样本 NN ────┘
    → 逐点支持度、UNKNOWN 判定、分支标签
    → 初始 MeVO ROI
    → 边界修正 refined_roi
    → 紧凑候选 MINI / BALANCED / RICH
    → 原始半径与补偿半径两份 SWC
    → VascularMD 拟合与表面建模
    → BALANCED 血管制造模型
    → I1 / O1 / O2 / O3 端口及衔接校正
    → 已验收四端口血管芯
    → 完整五面 ABS 倒模盒与血管芯合并
    → 姿态 / 支撑 / 几何检查及 Bambu 切片
    → candidate 0 和 15 独立打印包
```

当前 `compact_manifest.json` 记录的选择是：`source_component=4`、`source_level=semantic_refined`、默认候选 `BALANCED`，源 SWC 为 `refined_roi/semantic_refined/roi_part04_01_semantic_refined.swc`。默认流程使用 `refined_roi/`，不会因为存在 `refined_roi_run02/` 就自动切换。

当前倒模入口读取 `print_fixture_design_all_ports_aligned/` 中的已验收血管芯。正常重新生成盒体，不需要从 TopBrain、配准、半径拟合或端口修正重新开始。

`s1-5` 的开放框架是前一阶段方案；当前生产目标是 `s1-6` 的五面倒模盒。部分历史框架函数和结果仍是当前流程的依赖，不能仅按文件年龄删除。

### 5.1 s1-3 的四种数据模式

| `--source` | 实际读取的数据 | 用途 |
|---|---|---|
| `compact-brava` | `C/compact_manifest.json`、三候选 SWC/映射/表面及全局原始树 | 默认模式，显示当前紧凑 ROI |
| `manufacturing-stl` | `R/manufacturing_roi/BG001_RMCA_print_candidate.stl` 及配套清单/变换 | 检查较早的制造血管 STL |
| `topbrain-brava` | `.../nn_production/BG001/` 下的逐点/分支预测、ROI 和建模结果 | 检查迁移后的解剖候选 |
| `topbrain` | TopBrain 图像、标签和 labelmap | 提取并检查 TopBrain 原生标签区域 |

`manufacturing-stl` 依赖配套的来源与坐标变换，不是任意 STL 查看器。含完整盒体的最终 STL 使用 Bambu Studio 或最终 QC 图检查，不能直接替换进血管 ROI 模式。

### 5.2 两个容易误用的旧入口

`s1-2` 使用的全脑平滑 SWC 与当前语义迁移的原始 SWC 不同，节点编号也不能混用。其 landmark 必须对应具体文件；标注缺失时的 `NEEDS_MANUAL_REVIEW` 不表示当前紧凑候选缺失。

`transfer_topbrain_to_brava.py` 当前限定 BG001。切换其他受试者需要同步处理 TYPE 依据、源文件哈希、映射和输出隔离，不能仅改一个文件名就认为支持了新样本。

### 6.2 单位、半径与坐标系

BraVa 当前源 SWC 的 XYZ 和半径按 **mm** 使用；SWC 的数值字段是半径，不是直径。部分共享显示接口使用 **μm**，适配器把坐标和半径同时乘以 1000，一次完成单位转换。这不表示导出的打印模型扩大了 1000 倍。

STL 本身不记录长度单位，本项目制造导出按 mm 解释。不能再次乘 MRA 的体素间距，也不能只缩放坐标而不缩放半径。

原始解剖坐标、紧凑模型的打印坐标和最终盒体的打印姿态是不同阶段。叠加中心线、端口或网格前，先核对各自的 `print_transform*` 与来源清单；仅调整相机不会改变导出模型的坐标。

### 7.5 后续修改时从哪一步开始

| 本轮开发目标 | 应从哪里开始 | 必须同步检查的下游 |
|---|---|---|
| 只显示当前 ROI 或检查原始位置 | `s1-3 --source compact-brava --roi BALANCED` | 原始节点/边映射、单位及全局红色选区；不需要重跑制造 |
| 修改语义边界 | `tools/refine_bg001_rmca.py` 和新的修正输出 | 新紧凑候选、拟合表面、端口及倒模件不能继续冒用旧清单 |
| 修改分支数量、范围或半径补偿 | 紧凑配置副本及 `tools/compact_bg001_rmca.py` 的 `prepare/model/finish` | SWC 对照、映射、拟合后最小直径、表面、端口和打印检查 |
| 修正端口衔接 | `s1-4 --all-ports-aligned` 及对应配置副本 | 真实截面与表面接缝、所有端口、合并实体、后续盒体检查 |
| 复用现有血管芯重新生成倒模件或切片 | `s1-6 --output-root 新目录` | 盒体完整性、间距、当前工艺和新切片记录 |
| 仅再次取得 0、15 的已有文件包 | 导出工具的 `--source` 和 `--output` | 两种姿态必须已有唯一、通过检查的开启支撑切片 |

沿用现有端口基线进行校正时，可用如下命令将结果写入独立目录：

```bash
./run_python.sh s1-4_sacrificial_box_and_ports.py \
  --all-ports-aligned \
  --output-root outputs/ports_review_20260928_01
```

此入口依赖 `config/sacrificial_box_BG001.yaml` 中 `all_port_alignment.baseline_directory` 指定的既有壁面目标与路由。它是针对当前基线的对齐流程，不是对任意新 ROI 自动重新规划端口的通用命令。新血管几何发生变化时，需要先建立并验证对应的新基线，不能只替换 STL。

`s1-6` 通过 `config/abs_casting_mold_BG001.yaml` 的 `input.alignment_root` 选择血管芯，并读取对应汇总、解析后的配置、端口和盒体尺寸。若要接入上一条命令的新端口结果，应使用配置副本显式更新整组输入；程序不会自动选择最新输出目录。当前 `BOX_DIMENSIONS_REUSED` 策略也明确复用既有盒体尺寸，新的血管范围必须重新核对与它的适配关系。

上游的修正、制造和紧凑阶段带有历史保护检查；第 10 节列出的旧 UI 哈希冲突仍可能阻止重新计算。新建输出目录能避免覆盖，但不会自动消除输入快照冲突。应先核对并建立可追溯的新基准，不要跳过保护逻辑。

### 7.6 如何判断这条链已正确接通

从最终候选倒查时，依次确认：

1. 候选 `manifest.json` 的 `candidate_id` 为 0 或 15，`source_files` 和 `file_sha256` 对应实际文件；不要用历史 rank 代替 candidate ID。
2. `original_slice_audit.json` 与 3MF/G-code 对应同一次真实切片，模型、工艺、姿态变换以及血管特征保留检查一致。
3. 共同的 `M/abs_casting_mold_summary.json` 绑定已验收四端口血管芯，端口和盒体合并检查通过；`--skip-slicing` 结果仅证明几何阶段，不能代替切片证据。
4. 四端口汇总的 `source_stl` 指向 BALANCED 打印模型，拟合 SWC、映射与 `C/print_transform.json` 属于同一候选运行。
5. `C/compact_manifest.json` 确认 `BALANCED`、part04、语义修正层，以及本轮实际选择的原始节点；向上能回到 `R/` 的预测和原始 BG001 文件。

上述路径中出现旧工作区前缀时，按第 3 节的兼容链接解析到实际文件。本节给出的 89 节点等统计只描述当前交付版本；后续新 ROI 应以自己的清单和检查结果为准。

## 8. 日常操作与输出位置

所有命令都从项目根目录运行。示例中的新输出目录必须尚不存在；如果已经运行过，换一个新的名字。

### 8.1 查看当前紧凑血管 ROI

```bash
./run_python.sh s1-3_swc_roi_generate_MeVO.py --source compact-brava
```

左侧显示完整全局血管、ROI 长方体及红色选中部分，右侧显示所选区域。此模式加载已保存候选，不重新进行配准或制造建模。只检查数据加载时追加 `--no-gui`；检查另一次候选运行时指定 `--compact-results 新的候选目录`。

### 8.2 查看实际 TopBrain 数据配对

```bash
./run_python.sh s1-3_swc_roi_generate_MeVO.py --source topbrain --discover --no-gui
```

该命令打印实际病例与图像/标签路径，不生成新的打印模型。原生标签处理通常输出到 `outputs/topbrain_mevo/`，其几何缓存位于 `outputs/topbrain_mevo_cache/`。

### 8.3 使用已验收血管芯生成新的倒模件

```bash
./run_python.sh s1-6_abs_casting_mold.py \
  --output-root outputs/casting_mold_dev_20260928_01
```

输出包括 `final/`、`reference/`、`QC/`、`tables/`、`bambu/`、运行日志和中文报告。程序拒绝覆盖已有目录。默认配置中的正式目录已有验收结果，因此开发时应显式给出新输出目录。

只验证几何、不执行真实切片：

```bash
./run_python.sh s1-6_abs_casting_mold.py \
  --output-root outputs/casting_geometry_dev_20260928_01 \
  --skip-slicing
```

新切片读取本机 Bambu 当前配置，不能假定仍与交付包一致。2026-09-26 迁移测试时，本机当前工艺未能完整解析；该次运行明确跳过切片。执行完整切片前核对实际打印机、喷嘴、材料和工艺，并以新运行的 `bambu/discovery.json` 和切片记录为准。

### 8.4 重新导出已有两种姿态

```bash
./run_python.sh tools/export_abs_casting_candidates.py \
  --output exports/candidates_dev_20260928_01
```

输出目录包含两个候选子目录及对应 ZIP。该命令复用已经保存并核验的真实切片，不重新建模或发送打印任务。

使用另一轮倒模结果时增加 `--source 新的倒模运行目录`。该运行必须包含候选 0、15 及两者开启支撑的真实切片记录；仅完成 `--skip-slicing` 的目录不能提供这些打印文件。

### 8.5 检查文件完整性

```bash
./run_python.sh tools/verify_printing_workspace.py
./run_python.sh tools/verify_printing_workspace.py --full
```

第二个命令包含原始数据的全量哈希检查，耗时更长。它比较的是迁移时点的文件清单；后续正常开发修改过源码时也会报告变化。新增本指南不会自动成为旧迁移清单中的受保护文件。

## 9. 后续开发应该改哪里

| 想改变的内容 | 优先查看 | 输入输出边界 |
|---|---|---|
| 原始 SWC 解析或拟合 | `vascular_processing/swc_export.py`、`pipeline.py`、`vascularmd_adapter.py`、`branch_aic.py` | 保留原始 SWC；拟合另存，记录节点和拓扑变化 |
| TopBrain 标签读取 | `topbrain_dataset.py`、`topbrain_labels.py`、`topbrain_mevo.py` | 保持标签来源、物理坐标和 labelmap 一致 |
| 语义迁移与支持度 | `similarity_registration.py`、`semantic_ensemble.py`、`nn_support_gate.py`、`brava_branch_labels.py` | 改变参考样本、阈值或代码后，使用新的缓存/结果版本 |
| 语义 ROI 边界 | `mevo_refinement.py`、`tools/refine_bg001_rmca.py` | 不把工程半径筛选混称为解剖真值 |
| 紧凑模型复杂度与制造半径 | `compact_roi.py`、`manufacturing_roi.py`、紧凑 YAML | 同时导出原始/补偿 SWC，保留删枝、context 和映射 |
| 四端口衔接 | `all_port_attachment_run.py`、`port_attachment_alignment.py`、`surface_continuity_qc.py` | 以真实冻结表面为衔接依据；重新检查所有端口 |
| 最终盒体、间距与支撑 | `abs_casting_mold.py`、`casting_mold_qc.py`、`support_removal_qc.py` | 从已验收血管芯开始，单独输出新制造结果 |
| 切片读取与打印包导出 | `bambu_slice_adapter.py`、`bambu_casting_mold.py`、导出工具 | 保留真实切片、工艺、模型变换和对应哈希 |
| 更换 UI 数据源 | `compact_display_adapter.py`、`brava_display_adapter.py`、`manufacturing_stl_display.py` | 保持显示单位、原始节点/边映射和完整全局上下文 |

表中未带目录前缀的实现模块均位于 [vascular_processing/](vascular_processing/)。共享 SWC、图结构、ROI 数据类型及交互渲染位于 [utils/](utils/)，官方拟合实现位于 [third_party/vascularmd/](third_party/vascularmd/)。

### 开发时保持的约定

1. **先确定要修改哪一层。** 只改盒体就从已验收血管芯开始；只改显示数据就通过适配器接入，不隐式重跑语义迁移。
2. **为新实验使用新配置和新输出目录。** 修改参数后，记录输入文件、配置、代码版本和哈希；不要原地覆盖已经验收的 SWC、STL、切片或清单。
3. **默认入口不自动跟随最新目录。** 新 `refined_roi`、新紧凑候选或新血管芯需要显式传参，或在新的配置副本中更新输入。同步检查配套映射、变换与哈希。
4. **保留已接受的几何约束。** 当前端口采用 X/Y 盒壁，禁止 Z 端口；需要放宽间距时先核对原始拓扑的自适应补回路径，不能补到邻近但不相连的血管。紧凑路径长度允许自适应，60 mm 不是应重新加回的统一硬截断。
5. **修改数据时保持当前显示风格。** 保留全局血管、ROI 框和选中部分红色标识；相机、颜色、透明度等视觉调整应作为明确的单独需求处理。
6. **哈希冲突先查来源。** 源码正常迭代、路径变化、错误文件和模型变化是不同原因；不要删除检查或改写旧期望哈希来制造“通过”。需要更新基准时，另建版本并保留原证据。

## 10. 检查、日志与已知限制

测试位于 [tests/](tests/)。针对当前制造链，可先运行：

```bash
./run_python.sh -m pytest -q -p no:cacheprovider \
  tests/test_s1_6_abs_casting_mold.py \
  tests/test_all_port_attachment_alignment.py \
  tests/test_project_migration.py
```

不同阶段没有统一的一个状态字段。应查看本阶段 `*_summary.json`、`validation_results.json`、QC 表格和日志，而不仅检查是否生成 STL。

| 常见状态或现象 | 如何理解 |
|---|---|
| `EXACT_TOPBRAIN_LABEL` | 在 TopBrain 原生标签中按名称提取的区域；不能据此把 BraVa 迁移标签称为人工真值 |
| `ANATOMICAL_TRANSFER_CANDIDATE` | 参考样本迁移得到的解剖候选 |
| `PRINT_READY_CANDIDATE` | 该制造候选达到本阶段数字检查要求，仍不等于实物验证完成 |
| `READY_FOR_HUMAN_REVIEW` | 当前阶段成功并等待人工复核，仍需阅读该阶段警告 |
| `READY_FOR_HUMAN_REVIEW_WITH_BAMBU_PENDING` | 几何流程完成，但真实切片尚未完成或未获确认 |
| `NEEDS_ADJUSTMENT` | 该次流程失败或约束不满足，查看 `failures`、`run.log` 和失败报告 |
| `PROFILE_UNRESOLVED` | 当前切片工艺没有解析确认，不应把该运行当成已经生成可用打印文件 |

每次运行的 `run.log` 是过程记录，`tables/` 是定量依据，`QC/` 是图形检查，`*_report.md` 是阅读入口，`*_manifest.json` 和保护快照用于追溯。`bambu/` 保存真实切片证据；仅有程序退出码 0 不能代替模型与工艺核对。

2026-09-26 的迁移记录为：模型测试 475 项通过、1 项历史审计失败，旧 CFD/Network 回归 49 项通过。那一项失败是早期制造快照保存的 `s1-3` 哈希早于后来已验收的可视化版本，迁移没有修改该 UI。旧 `tools/compact_bg001_rmca.py --stage verify` 也可能拒绝这份快照，并写入其验证报告；它不是纯只读核验入口。上述数字是历史证据，不是本指南编写当天的新测试结果。

当前 `s1-6` 的几何重建曾验证与已验收最终 STL 逐字节一致；candidate 0、15 的 STL、3MF 和 G-code 也完成了导出一致性检查。具体记录见 [迁移与清理记录](docs/迁移与清理记录.md)。
