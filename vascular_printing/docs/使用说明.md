# 如何使用当前血管打印代码

## 1. 只想查看或使用现成打印件

进入项目根目录的 `deliverables/`。`candidate_0/` 是正放方案，`candidate_15/` 是侧放方案；同名 ZIP 是可复制到其他电脑的完整包。

在 Bambu Studio 中打开包内的 `_support_ON.3mf`。3MF 已包含模型、姿态、工艺和真实切片；`.stl` 只包含对应姿态的几何，重新导入 STL 后需要再次设置工艺与切片。单独的 `.gcode` 与 3MF 内保存的内容一致。

两种姿态使用相同的血管和盒体，区别是摆放方向和对应支撑。包内 `print_orientation.png` 可直观看到摆放方式，`manifest.json` 记录候选编号、切片设置及校验结果。历史 3MF 中 `orientation_candidate_04` 的内部名称是排序编号，对应本次 candidate 15，不能据此误认成 candidate 4。

## 2. 查看血管 ROI 与全局位置

在具有图形界面的终端中运行：

```bash
cd /home/lzy/projects/vascular_printing
./run_python.sh s1-3_swc_roi_generate_MeVO.py --source compact-brava
```

该入口读取已保存的 MINI、BALANCED、RICH 区域；默认 BALANCED。左侧保留完整全局血管和当前 ROI 标记，右侧显示所选区域。迁移没有改变可视化风格。

如果只核对数据加载，不打开窗口：

```bash
./run_python.sh s1-3_swc_roi_generate_MeVO.py --source compact-brava --no-gui
```

查看之前独立的 manufacturing 血管 STL：

```bash
./run_python.sh s1-3_swc_roi_generate_MeVO.py --source manufacturing-stl
```

这个模式依赖 manufacturing 清单和坐标变换，不是任意 STL 查看器。最终含盒体的两个候选请用 Bambu Studio 和 `deliverables/QC/` 检查，不要把盒体 STL 强行替换到血管 ROI 模式中。

## 3. 重新生成一体式 ABS 倒模件

当前正式入口是 `s1-6_abs_casting_mold.py`，参数文件为 `config/abs_casting_mold_BG001.yaml`。它读取已验收的四端口血管芯，生成无装配孔的五面盒体，执行实体合并、PDMS 间距、支撑通路、姿态及本地 Bambu 切片检查。

```bash
./run_python.sh s1-6_abs_casting_mold.py \
  --output-root outputs/casting_mold_run_02
```

`casting_mold_run_02` 必须是尚不存在的目录；已有结果会拒绝覆盖。新结果包括 `final/`、`reference/`、`QC/`、`tables/`、`bambu/`、中文报告、JSON 汇总及运行日志。

只做几何诊断、不调用切片器时可追加 `--skip-slicing`。此时结果不等同于完成真实切片。任何入口都不会发送文件给打印机或启动打印。

重新切片会读取本机 Bambu Studio 的当前配置。现成候选包使用 P1S、0.4 mm 喷嘴和 ABS；迁移检查时，软件当前选择的是 X1 Carbon、0.2 mm 喷嘴，且对应官方工艺未能解析。如果希望复现原候选，请先在 Bambu Studio 中选择原来的打印机、喷嘴、ABS 和 0.20 mm Standard 工艺，再运行完整命令；不要把“几何通过、切片待完成”的结果当成可直接打印的新文件。现成候选包的切片参数与内容没有变化。

四端口路径、衔接和制造半径已验收。正常重新生成盒体不需要重新运行 TopBrain、配准、语义迁移、VascularMD 或端口对齐。`s1-4`、`s1-5` 保留了历史流程及当前仍使用的依赖，不是日常重新生成最终盒体的首选入口。

## 4. 再次导出 candidate 0 和 candidate 15

```bash
./run_python.sh tools/export_abs_casting_candidates.py \
  --output exports/candidate_comparison_02
```

输出目录也必须尚不存在。该工具复用已经核验的真实切片，分别导出 STL、3MF、G-code 和 ZIP，并检查模型姿态、文件哈希、G-code 与 3MF 的一致性。它不会重建血管或重新搜索姿态。

若要从另一次完整倒模运行中导出，增加 `--source outputs/对应运行目录`。该运行需保存候选 0、15 和两者开启支撑的真实切片记录。

## 5. 运行检查

```bash
./run_python.sh -m pytest -q -p no:cacheprovider \
  tests/test_project_migration.py \
  tests/test_s1_6_abs_casting_mold.py \
  tests/test_all_port_attachment_alignment.py \
  tests/test_s1_5_sacrificial_print_frame.py
```

迁移回归结果保存在 `migration/20260926/`，最终模型原来的测试和报告仍保留在其输出目录中。历史哈希记录按原文保留；路径适配代码的修改单独记录原文、差异及前后哈希，不会把这类修改伪装成“字节未变”。

也可以只读检查迁移后的文件是否完整：

```bash
./run_python.sh tools/verify_printing_workspace.py
# 连原始数据一起逐文件校验，耗时更长：
./run_python.sh tools/verify_printing_workspace.py --full
```

全套测试有一项已确认的历史审计冲突：早期制造阶段记录的 `s1-3` 哈希早于后续已验收的可视化版本。当前 `s1-3` 在迁移前后完全相同。`tests/test_manufacturing.py::test_all_frozen_sources_and_semantic_layers_unchanged` 因此仍会失败，旧的 `tools/compact_bg001_rmca.py --stage verify` 也会报告冲突。当前倒模件、两种候选和 ROI 显示不受影响；本次没有通过改写旧哈希掩盖冲突。详见 [迁移与清理记录](迁移与清理记录.md)。

## 6. 需要修改什么参数

| 目的 | 入口或位置 |
|---|---|
| 当前 ABS 盒体、支撑探针、姿态搜索参数 | `config/abs_casting_mold_BG001.yaml` |
| human 样本与 ROI 数据配置 | `configs/swc_roi_generate_human.yaml` |
| mouse 样本与原始 / AIC 数据选择 | `configs/swc_roi_generate.yaml`、`configs/swc_roi_generate_mouse_raw.yaml` |
| TopBrain 根目录及标签配置 | `configs/topbrain_mevo.yaml`、`data/TopBrain/` |
| 查看模型而不重新计算 | `s1-3_swc_roi_generate_MeVO.py` |
| 原生 VascularMD 处理说明 | `vascular_processing/README.md` |

不要直接编辑已验收 STL、SWC 或历史输出中的 `protected_before.json` 来消除检查错误。需要产生新设计时使用新输出目录，保留原始验收依据。
